# 操作卡 04：上机与运行监控

> 对应模块 M4；上游：文库 QC；下游：干实验分析。

## 目的

完成**等摩尔 pooling、PhiX 加入、变性稀释与上机**，并在运行中判断质量。

## 前置检查

- [ ] 每个文库有 qPCR 摩尔浓度与片段长度。
- [ ] pooling 表已按 nM 计算并复核。
- [ ] PhiX 比例已按文库多样性确定。
- [ ] 测序仪、流动池/芯片、试剂在有效期内。
- [ ] 平台说明书中的 loading 浓度与变性流程已确认。

## 材料与设备

测序仪与配套试剂、流动池/芯片、PhiX、变性缓冲液、稀释液、低吸附管、移液器。

## 步骤

1. **等摩尔 pooling**：按 `tools/calc_molarity.py --pool` 或手算体积，逐个加入，补稀释液至目标体积。
2. **加入 PhiX**：常规 1%；低多样性文库（16S/扩增子）≥25%（见已核对 Illumina 页）；按同一体系混匀。
3. **变性**：Illumina 用 NaOH 变性、中和（MGI 的变性在环化阶段，不在上机前）。
4. **稀释**：稀释到平台规定的 loading 浓度；注意 1 nM = 1000 pM。
5. **上机**：按平台流程装载，记录 run 编号、试剂批号、loading 浓度。
6. **监控**：跟踪簇密度/纳米球密度、PF%、Q30、产出。

## 每步原理与技巧（两平台化学 + 三个关键点）

> 来源锚点：[7] SBS、[8] DNB 见[文献索引](../references/文献索引.md)；参数见已核对协议 [Illumina 上机](../05-厂家方案/上机-Illumina.md)、[MGI 环化](../05-厂家方案/上机-MGI环化.md)。

### 1. 边合成边测序（Illumina SBS）是怎么"读"出碱基的

- **为什么**：文库单链固定在流动池表面，先经桥式 PCR 扩增成"簇"（同一分子的上千拷贝扎堆）。然后每轮**同时加入四种荧光标记的可逆终止核苷酸**——聚合酶只接一个进去就停（终止基团），拍一张照片按颜色读出这一个碱基，再把荧光和终止基团一起切掉，进入下一轮 [7]。
- **技巧**：Q30 随循环数缓慢下降是正常的（簇内不同步累积）；**骤降**才查试剂/温控（见[案例 12](../05-实践/故障案例库.md)）。

### 2. MGI 平台（DNBSEQ）为什么叫"纳米球"

- **为什么**：文库先环化成单链，再滚环扩增成一团 **DNA 纳米球（DNB）**，纳米球自组装到阵列载片，用联合探针锚定**合成**（cPAS，连接法，源自 Complete Genomics 的 cPAL）逐碱基读序 [8]。
- **技巧**：扩增在纳米球内部进行、不是表面成簇，但同样要监控**纳米球密度**——过载欠载一样影响产量；且必须先完成环化与 DNB 制备才能上机。

### 3. 簇密度为什么是 loading 的死穴

- **为什么**：簇太密，相邻簇的荧光信号混在一起分不出来；太稀，通量浪费、产量掉。簇密度由 loading 浓度直接决定——loading 的 nM 换算错一位，就是[案例 13](../05-实践/故障案例库.md)的产量腰斩。
- **技巧**：loading 用 qPCR 摩尔浓度换算、双人复核；换流动池/试剂批次后重新核对平台推荐 loading 区间。

### 4. 为什么上机前要"变性"

- **为什么**：双链文库必须先解成单链，才能杂交到流动池/载片上、进而成簇。NaOH 变性就是把双链拆开；变性后要快、要冰上，否则单链会重新退火，loading 效率下降。
- **技巧**：NaOH 变性是 **Illumina 专属**上机步骤；MGI 的变性发生在**环化阶段**（95 ℃ 3 min），上机装载的已是成环单链（见 [MGI 环化页](../05-厂家方案/上机-MGI环化.md)），别把 Illumina 的变性步骤套到 MGI。

### 5. PhiX 是干什么的

- **为什么**：PhiX 是一段**序列已知**的小噬菌体基因组对照文库：① 校准碱基识别的错误率（对照 Q30）；② 低多样性文库（16S、扩增子）碱基组成单一，会造成颜色失衡、簇定位困难，掺入 PhiX 补多样性。
- **技巧**：常规加 **1%**、低多样性（16S/扩增子/单一转录本 >25%）加 **≥25%**（已核对 [Illumina 页](../05-厂家方案/上机-Illumina.md)）；PhiX 与 pool 必须同一体系混匀，别先稀释再加。

## 判断标准

| 指标 | 正常 | 异常处理 |
|------|------|----------|
| 簇密度 | 在平台推荐区间 | 偏高/偏低 → 调整 loading |
| PF% | 平台常见范围 | 低 → 查试剂、流动池、簇生成 |
| Q30 | 达到平台承诺 | 低 → 查试剂、温控、流动池 |
| 产出 | 接近预期 | 低 → 查 pooling 比例与读长设置 |

> 具体阈值以平台与试剂版本为准；不同平台差异大，不照搬旧参数。

## 记录（对应 `模板/pooling计算表.csv`）

文库编号、浓度 nM、目标占比、取样体积、稀释液体积、PhiX 比例、loading 浓度、run 编号、Q30、PF、产出。

## 常见问题

| 现象 | 原因 | 处理 |
|------|------|------|
| 簇密度过低 | loading 不足、变性不充分 | 提高 loading、检查变性 |
| 簇密度过高 | loading 过量 | 稀释后重上 |
| Q30 低 | 试剂/流动池/温控问题 | 换试剂、报修 |
| 低多样性报警 | 文库多样性低 | 提高 PhiX 比例 |

## 变性、稀释与 loading

1. **（Illumina）**按平台要求用 0.2 N NaOH 变性 5 min，随后加中和缓冲液；MGI 的变性在环化阶段完成，上机前无需 NaOH 变性。
2. 立即置于冰上，避免重新退火。
3. 用预冷稀释液稀释到平台规定浓度；1 nM = 1000 pM。
4. 加入 PhiX 后轻柔混匀，避免气泡。
5. 上机前检查液面、气泡与废液瓶。

## 运行监控与排查

| 阶段 | 看什么 | 异常处理 |
|------|--------|----------|
| 簇生成 | 簇密度/纳米球密度 | 偏低查 loading 与变性；偏高稀释重上 |
| 测序早期 | PF%、Q30 | 低 PF 查试剂与流动池；低 Q30 查温控 |
| 运行中 | 产出曲线 | 偏离预期查读长设置与 pooling 比例 |
| 结束后 | 总产出、Q30、比对率 | 记录批号，异常留样复测 |

## 技巧与避坑

- 变性后操作要快，冰上放置；室温久放会重新退火，loading 效率下降。
- 稀释液预冷，低吸附管，减少文库吸附损失。
- PhiX 与 pool 必须同一体系混匀，不要先稀释再加。
- 低多样性文库（16S、扩增子）适当提高 PhiX 比例，避免低多样性报警。
- 每次运行记录流动池/芯片批号、试剂批号、loading 浓度，异常时才能追溯。
