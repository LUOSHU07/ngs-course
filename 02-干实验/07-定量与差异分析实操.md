# 实操 07：定量与差异分析（M7）

> 目标（对应大纲 M7）：从 BAM 得到表达矩阵与差异基因，产出**表达矩阵 + 差异结果表 + 两张图**。

## 一、练习数据（二选一）

- **路径 A（零下载，推荐先跑通）**：Bioconductor 示例包 `airway`，内置 8 个 RNA-seq 样本的计数数据与分组信息，R 内直接加载，跳过整个命令行流程，专练差异分析。
- **路径 B（全流程）**：在 SRA/GEO 选一个**小型**公开 RNA-seq 项目（数据量 <1 GB，便于下载），用 `fasterq-dump` 取回 FASTQ 后跑完整流程。选项目时记录：物种、测序类型（单/双端）、分组设计——这三项决定后续每条命令的参数。

## 二、环境

- 命令行工具（conda 安装，与课程 [setup_ngs_env.sh](../tools/bohrium/setup_ngs_env.sh) 一致）：
  `fastqc`、`trim-galore`、`hisat2`、`samtools`、`subread`（含 featureCounts）。
- R 包：`DESeq2`（路径 A 另需 `airway`）。

## 三、命令流（路径 B）

```bash
# 0. 工作目录与参考基因组（hisat2 索引：官网下载对应物种预建索引，或自行 hisat2-build）
mkdir -p qc bam counts

# 1. 原始数据质控
fastqc fastq/*.fastq.gz -o qc/
# 看三件事：per base quality（Q30 线）、adapter content、duplication 估计

# 2. 接头与低质修剪（双端示例；单端去掉成对参数）
trim_galore --paired --quality 20 --fastqc \
    fastq/S1_R1.fastq.gz fastq/S1_R2.fastq.gz -o qc/

# 3. 比对（hisat2；索引前缀按你的基因组改）
hisat2 -x ref/genome -p 8 \
    -1 qc/S1_R1_val_1.fq.gz -2 qc/S1_R2_val_2.fq.gz \
    -S bam/S1.sam
samtools sort -@ 8 -o bam/S1.bam bam/S1.sam && samtools index bam/S1.bam

# 4. 定量（featureCounts；-p 双端；-t exon -g gene_id 按 GTF 属性）
featureCounts -T 8 -p --countReadPairs \
    -a ref/genes.gtf -o counts/all_samples.txt bam/*.bam

# 5. 整理成 DESeq2 输入：取 counts/all_samples.txt 的基因列与各样本计数列，
#    另建 design.csv（两列：sample,condition，顺序一致）
```

> 每一步都看输出再往下走：FastQC 报告、trim_galore 的保留率、hisat2 的 overall alignment rate（低于 ~70% 先查物种/索引是否匹配）、featureCounts 的 assigned 比例（偏低先查 GTF 与参考版本是否一致、**链特异性参数 `-s` 是否与建库方案匹配**——dUTP 链特异性文库设反 `-s` 会导致 assigned 骤降，见文献索引 [9]）。

## 每步原理与技巧（5 命令：为什么这么做）

> 锚点：工具官方文档（FastQC / Trim Galore / HISAT2 / featureCounts / DESeq2）+ 文献索引 [9]（链特异）；通俗只改措辞、不改机制。本卡命令经人工核对（B 级），未在本机 Linux 实测。

### 1. FastQC：质量分到底是什么

- **为什么**：测序仪每读一个碱基就给一个质量分 Q（Phred 标度），换算关系是 **Q = −10·log₁₀(错误概率)**——Q30 就是出错概率 0.1%、Q20 是 1%。FastQC 把几十万条 read 的 Q 值统计成曲线和分布，让你一眼看到"哪里在变差"：per-base quality 尾部下滑（读长末端信号衰减、簇内不同步累积，见 [04 卡 SBS](../01-湿实验/04-上机与运行监控.md)）、adapter content 上升（read 读穿了插入片段、开始测进接头）、duplication 高（PCR 重复/文库复杂度低）。
- **技巧**：先**不 trim 直接跑 FastQC**，确认问题类型再决定怎么剪；RNA-seq 的高重复率可能只是高表达基因，别一律判失败；过表达序列（overrepresented sequences）提示污染或低多样性。

### 2. Trim Galore：为什么要"剪"

- **为什么**：低质碱基和接头序列会错配到参考基因组上、拉低比对率。Trim Galore 从 **3' 端**开始、把质量低于阈值的碱基剪掉（单碱基阈值 + 累计分找最佳切点，BWA 同款算法；"滑动窗口看平均质量"是 Trimmomatic/fastp 的做法，别混）；接头则是"读穿插入片段"多测出来的序列，按已知接头序列认出来再剪。
- **技巧**：`--quality 20` 是 Q20 阈值（1% 出错率），不是越高越好——**过度 trim 会让 read 太短、唯一比对率反而下降**；双端必须成对剪（`--paired`），否则两端成对关系被破坏、产生孤儿 read。

### 3. HISAT2：RNA 比对为什么比 DNA 难

- **为什么**：RNA-seq 的 read 来自成熟 mRNA，**跨过了内含子**——一条 read 可能前半段在外显子 1、后半段在外显子 3。普通比对器（bwa 这类）只会在基因组上"直线"找，跨内含子的 read 就找不着。HISAT2 用分层 FM 索引 + 剪接位点信息，专门处理这种"剪接感知"比对，所以 RNA 用 HISAT2/STAR，DNA 用 bwa。
- **技巧**：比对率 <~70% 先查**物种和索引**是否匹配（这是最便宜的一步）；链特异性建库（dUTP）要在下一步 featureCounts 设对应的 `-s`，比对本身不用设。

### 4. featureCounts：read 怎么"归"到基因

- **为什么**：把比对上的 read 按 GTF 注释的外显子坐标"数"到每个基因头上——read 落在外显子里就记一分。双端测序用 `--countReadPairs`，把一条片段的两端算成**一份**（而不是两份），否则表达量翻倍。
- **技巧**：`-t exon -g gene_id` 是按"外显子"计数、按"gene_id"属性归并；`-s` 必须与建库链特异方向一致——**设反了 assigned 比例会骤降**（见文献索引 [9]）；GTF 版本要和参考基因组版本成对，版本错位会让大量 read 数不进去。

### 5. DESeq2：为什么不能直接比 counts

- **为什么**：原始 counts 受**测序深度**（谁测得深谁 counts 多）和文库大小影响，不能直接拿两个样本比大小。DESeq2 先给每个样本算一个 **size factor**（缩放系数）把 counts 归一化，再用**负二项分布**建模——counts 是离散整数、而且方差大于均值（过离散），普通正态/泊松都不合适；最后做 Wald 检验给出 log2FoldChange 和 padj。**padj 是 BH 校正后的错误发现率，不是"这个基因真的差异的概率"**。
- **技巧**：低表达基因（总计数 <10）先过滤——它们没有检验功效，留着只会稀释校正；**样本顺序错位是最常见的毁灭性错误**（脚本里 stopifnot 拦截）；先看 PCA 是否按 condition 聚类——按批次聚类说明批次效应主导，得把批次写进 design。

## 四、差异分析（R）

```bash
Rscript ../tools/deseq2_template.R counts_for_deseq.csv design.csv results/
```

脚本逻辑（[deseq2_template.R](../tools/deseq2_template.R)，可打开对照）：

1. 读计数矩阵与分组表，校验样本顺序一致（**顺序错位是最常见的毁灭性错误**，脚本会 stopifnot 拦截）；
2. 低表达过滤（总计数 <10 的基因不提供检验功效）；
3. `DESeq()` 估计 size factor 与离散度、Wald 检验；
4. 输出：`deseq2_results.csv`（按 padj 排序）、`volcano.png`、`pca.png`。

路径 A 的等价入口（R 内）：

```r
library(airway); data(airway)
# airway 是 RangedSummarizedExperiment（不是 DESeqDataSet），需先转换；
# 其 colData 列为 cell/dex（没有 condition 列），设计公式按实际列名写：
dds <- DESeqDataSet(airway, design = ~ cell + dex)
# dds <- DESeq(dds) 之后与模板第 3、4 步相同；结果解读关注 dex 的系数
```

## 五、结果解读的边界（大纲要求）

- padj 是 BH 校正后的错误发现率，不是"该基因真的差异的概率"；
- |log2FC| 小但 padj 显著：生物学意义需自行判断，统计显著 ≠ 重要；
- PCA 先看**分组是否按 condition 聚类**——按批次聚类说明批次效应主导，需在设计中纳入批次项（`~ batch + condition`）；
- 火山图与热图是探索性展示，不构成证据本身。
