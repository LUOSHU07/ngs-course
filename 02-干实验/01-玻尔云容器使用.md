# 玻尔云容器使用（S3 执行环境）

> 依据 Bohrium 官方文档整理（2026-11）。界面与机型以平台实际为准；标“待实测”的步骤需在账号内确认。

## 1. 为什么用玻尔跑 S3

- 基础镜像自带 Ubuntu、Python 3.10、Anaconda、git、wget、rsync，省去本机装环境。 [镜像中心](https://bohrium-doc.dp.tech/docs/userguide/image)
- 容器镜像保证环境可复现，适合教学与交接。
- 按量计费，S3 的测试数据很小，几分钟即可跑完。

## 2. 账号、项目与 AccessKey

1. 在 [bohrium.dp.tech](https://bohrium.dp.tech/home) 注册或登录。
2. 用户中心充值（作业与节点按量扣费）。
3. 新建项目，记下 **project_id**（提交作业要用）。 [快速开始](https://bohrium-doc.dp.tech/en/docs/quickstart/FirstRun/)
4. 在设置页生成 **AccessKey**；重新生成会使旧 Key 失效。

## 3. 交互方式：先选入口，再选工具

### 3.1 两种入口

| 入口 | 用途 | 操作 |
|------|------|------|
| 容器节点（管理节点） | 装环境、调试、交互运行 | Nodes → Create Container |
| 作业（job） | 批量、正式运行 | `job.json` + `bohr job submit` |

S3 建议先用**容器节点**把流程跑通，再用**作业**固化。

### 3.2 工具对比

| 方式 | 适合 | 优点 | 限制 |
|------|------|------|------|
| Web Shell | 首次登录、临时检查 | 零配置，root 直登 | 浏览器内操作，长任务与复制粘贴较弱 |
| `bohr node connect` | 日常终端 | 免密 SSH，一条命令 | **交互式**，不适合脚本/Agent |
| 手动 SSH | 任意 SSH 客户端 | 通用，可用 scp/rsync | 需查 IP 与密码，节点重建后变化 |
| VS Code Remote-SSH | 多文件开发调试 | 编辑、终端、Git 一体 | 需配 SSH；大目录索引慢 |
| JupyterLab | 教学、探索性分析 | 图文并茂、可保存 | 需端口映射；不适合长任务 |
| `bohr job` CLI | 批量、可复现 | 提交、日志、下载、`--dry-run` | 需写 `job.json` |
| Python SDK / API | 平台集成 | 全自动 | 学习成本高 |

### 3.3 推荐路径

- **人写代码**：VS Code Remote-SSH 编辑 + `bohr node connect` 跑命令。
- **批量/可复现**：`bohr job submit --dry-run` 校验 → 正式提交 → `bohr job log/download`。
- **Agent/自动化**：只用非交互命令（`node list/get`、`job list/describe/log/download`）；`node connect` 是交互式，不要放进脚本。
- **教学演示**：JupyterLab 讲原理，CLI 跑流程，两者分工。

## 4. 创建容器节点

1. 进入 Nodes，点 Create Container。
2. 镜像选 CPU 基础镜像：`registry.dp.tech/dptech/ubuntu:20.04-py3.10`。
3. 选择所属项目；机型、系统盘、自动关机按需（测试选最小 CPU 机型即可）。
4. 状态从 Preparing 变为 Running 后，点 Connect → **Open Web Shell**，以 root 登录。
5. 也可用本地 SSH 或 VS Code 连接；开发机 50001–50005 端口对外可用。

> 容器节点本身已是 Docker 环境，**不能在其上再创建 Docker**；需要 Docker 开发时用虚拟机镜像。 [镜像中心](https://bohrium-doc.dp.tech/docs/userguide/image)

## 5. 目录约定

| 目录 | 用途 | 生命周期 |
|------|------|----------|
| `/personal` | 个人数据盘 | 持久 |
| `/share` | 项目共享空间（默认 1 TB） | 持久，节点释放不删除 |
| 系统盘 | 环境与代码 | 转镜像时只保存系统盘 |

课程文件建议放 `/share/ngs-course`，参考基因组等大文件也放这里。 [Web Shell](https://bohrium-doc.dp.tech/en/docs/userguide/WebShell)

## 6. 安装生信环境

镜像自带 Anaconda，直接用 conda 建环境：

```bash
bash tools/bohrium/setup_ngs_env.sh
```

脚本等价于：

```bash
conda config --set channel_priority strict
conda create -y -n ngs -c conda-forge -c bioconda \
  fastqc fastp bwa-mem2 samtools subread salmon multiqc
conda activate ngs
```

国内网络慢时，先配置 TUNA/BFSU 镜像再执行。

## 7. 上传课程与数据

三种方式任选：

1. 网页文件树拖拽上传到 `/personal`；
2. 本地 `scp -r ngs-course user@<节点地址>:/share/`；
3. 节点内 `git clone` 或 `wget` 公网地址。

没有真实数据时，用合成数据先验证流程：

```bash
python tools/bohrium/make_testdata.py --out data/s3test
```

会生成 `ref/genome.fa`、`ref/annotation.gtf`、`raw/sample_R1.fastq.gz`、`raw/sample_R2.fastq.gz`。

## 8. 跑 S3 测试流程

```bash
conda activate ngs
cd /share/ngs-course
bash tools/bohrium/run_pipeline.sh data/s3test
```

预期产出：

```text
data/s3test/trimmed/sample_R1.fq.gz
data/s3test/trimmed/sample_R2.fq.gz
data/s3test/bam/sample.bam
data/s3test/bam/sample.bam.bai
data/s3test/counts/counts.txt
```

## 9. 提交作业（可选）

填好 `tools/bohrium/job.example.json` 的 `project_id`、`machine_type`，另存为 `job.json`：

```json
{
  "job_name": "ngs-s3-test",
  "command": "bash tools/bohrium/run_pipeline.sh data/s3test",
  "log_file": "logs/run.log",
  "backward_files": ["data/s3test/counts/", "logs/run.log"],
  "project_id": 0000,
  "platform": "ali",
  "machine_type": "<从价格页复制的 CPU 机型>",
  "job_type": "container",
  "image_address": "registry.dp.tech/dptech/ubuntu:20.04-py3.10"
}
```

提交、看日志与取回：

```bash
# 1) 先校验，不产生资源
bohr job submit -i job.json --input_directory ./ --dry-run

# 2) 正式提交
bohr job submit -i job.json --input_directory ./

# 3) 取日志与结果（<BOHR_ID> 来自 bohr job list）
bohr job log <BOHR_ID> --out ./logs
bohr job download <BOHR_ID> --out ./results
```

字段说明：`command` 为节点内执行的命令；`log_file` 可实时查看；`backward_files` 为结束后回传的文件；`image_address` 必须是完整地址。 [运行容器任务](https://bohrium-doc.dp.tech/docs/bestpractice/Docker) [Job Commands](https://bohrium-doc.dp.tech/en/docs/bohrctl/job/)

## 10. 计费与清理

- 节点与作业按机型、时长计费；跑完在 Nodes/Jobs 页面**关机或删除节点**。
- `/share` 数据不会随节点释放删除，但会占用项目存储配额。
- 测试任务建议选最小 CPU 机型，避免 GPU 机型空转。

### 10.1 命令行自检

```bash
bohr auth status          # 是否登录、凭证来源
bohr node list            # 空列表时也会提示余额是否充足
bohr node resources       # 可用 CPU/GPU 机型与磁盘大小
bohr machine list -c all  # 机型与单价
bohr node create ... --dry-run   # 只校验，不创建
```

创建节点或提交作业前，先确认余额；余额不足时平台会拒绝创建。

## 11. 限制与常见坑

| 坑 | 说明 |
|----|------|
| 镜像地址不完整 | 必须 `registry.dp.tech/...`，不能只写镜像名 |
| `-p` 简写不存在 | 当前 CLI 用 `--input_directory ./`，旧教程的 `-p` 会报错 |
| 参数连字符 | CLI 标志是 `--project-id`；`job.json` 字段是 `project_id` |
| 磁盘大小受限 | `--disk_size` 仅支持 20/40/80/100 GB |
| 自动关机单位 | `--turnoff_after` 是**小时**，默认 24；`-1` 表示永不关机 |
| 容器内再跑 Docker | 不支持；需 Docker 开发用虚拟机镜像 |
| 转镜像丢数据 | 只保存系统盘，数据放 `/share` 或先拷贝 |
| job.json 语法 | 最后一个字段后不能有逗号 |
| 并行任务镜像 | 仅支持公共容器镜像 |
| 端口 | 开发机仅 50001–50005 对外 |

## 12. S3 完成标准

- [ ] 节点内 `fastp --version`、`bwa-mem2 version`、`samtools --version` 均可执行。
- [ ] `run_pipeline.sh` 产出 BAM、BAI、counts 三个结果。
- [ ] 记录镜像地址、机型、耗时与费用，写回审查报告。
